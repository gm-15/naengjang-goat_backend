# POS 마감·배송 입고·운영 리포트 및 두 시점 알림 연결

영업 종료 후 POS 엑셀을 올리면 메뉴 레시피 기준으로 재고를 즉시 차감하고 당시 판매·소비량을 리포트에 저장합니다. 외부 구매 기록은 배송 대기로 남고, 수령 후 입고 요청에서만 재고를 늘립니다. 판매 반영 직후와 다음 영업 시작 3시간 전에 각각 발주 판단을 저장·발송합니다.

- 점주별 DB 잠금 및 전체 트랜잭션으로 판매/입고 중복과 부분 차감 방지. 동일 파일 재요청은 기존 결과 반환, 같은 영업일의 다른 파일은 409.
- 사용 가능한 재고·최근 30일 POS 소비로 부족 예상/추천량 계산. 과거 판매 리포트는 당시 스냅샷 유지.
- 알림 이벤트별 중복 방지, 커밋 후 FCM 발송, 실패 재시도·미설정/토큰 대기·만료 상태 제공. 종료 전/가격 수집 직후 알림은 기본 발송 경로에서 제외.
- 인증/가격 JSON/단위 계약 보완. 기존 migration checksum을 유지하면서 빈 DB bootstrap 및 신규 workflow migration 추가.
- demo 전용 합성 데이터·오늘 날짜 POS 샘플·동일 영업 전 로직 수동 실행, API/팀원별 작업/시연 문서 제공.

검증: Java 21/MySQL 8/Redis 7에서 `gradlew build`, 전체 테스트 25개(새 workflow 14개, 기존 동시성 4개·Redis 장애 2개 등) 통과. 빈 DB bootstrap callback + V001~V009, 모의 V008 DB→V009 업그레이드, 실제 HTTP 로그인→POS→리포트→판단→발주→입고→영업 전 이벤트 검증. 재고 6,000→2,000→발주 후 2,000→입고 후 4,000g, 매출 64,000원·소비 4,000g·제안 1,300g 확인.

실제 Firebase 서비스 계정이 없어 HTTP 검증의 발송 상태는 NOT_CONFIGURED입니다. 푸시 성공/재시도 경로는 mock 검증이며, 실기기 수신 및 앱 E2E는 프론트 연결 후 필요합니다. 실제 KAMIS/EKAPE/온라인 가격 데이터 검증은 데이터 담당 작업입니다. 기존 DB는 migration 이력/수동 컬럼과 대조해야 하며 자동 repair/reset은 수행하지 않습니다.
