| POS 엑셀 처리 | 완료 | 업로드·검증·메뉴 연결·판매 기록·레시피 차감, 전체 롤백·동시 요청/파일 중복 방지 검증 |

| 시연 준비 | 새 DB 재생성 방식으로 완료 | 직접 만든 메뉴·BOM·판매·가격·재고 fixture, 오늘 POS 샘플, HTTP 반복 검증. 서로 다른 새 전용 DB에서 숫자 재현. 같은 DB 초기화 버튼/자동 reset은 미구현 |

## 확인한 수치

- 전체 자동 테스트 25개 및 clean build 통과.
- POS 8개 판매 → 매출 64,000원·재료 4,000g 소비.
- 재고 6,000g → POS 반영 2,000g → 주문 기록 2,000g 유지 → 입고 4,000g.
- 합성 30일 이력 기준 일평균 1,100g, 다음 발주일까지 3일, 권장 1,300g.
- 빈 DB 생성과 모의 V008→V009 업그레이드 확인.

## 총괄에게 남은 실제 검증

- Firebase 서비스 계정 설정 후 실제 FCM 요청 성공 확인.
- 김건우의 앱 연결 후 실제 기기의 파일 업로드·두 푸시 수신·알림 이동 확인.
- 심상묵의 실자료 검증 후 가격/소모량/발주량 재확인.
- 통합 환경 고정, 전체 시나리오 E2E와 4분 리허설.

위 서버 구현을 넘기고 팀원 작업을 시작할 수 있는 상태다. PR 생성/merge, 실제 기기 푸시, 실제 가격 검증 및 앱 E2E까지 완료했다고 표현하지 않는다.
