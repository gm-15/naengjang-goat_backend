# 냉장GOAT 백엔드 마무리 및 연동 자료

기준: 백엔드 `gm-15/naengjang-goat_backend/main` d7814bb + 이번 변경. 프론트·모바일은 `keonU206/smu_capstone_project` 0628fa1의 `frontend/`, `mobile/`만 확인. 팀원 레포의 백엔드는 기준으로 사용하지 않았다.

## 확정한 점주 흐름

1. 운영 전: 반영된 판매 자료 기준 재고·부족 예상·가격 근거 확인. 외부 사이트에서 결제한 주문을 앱에 기록. 배송 대기 표시. 받은 뒤 입고 버튼으로 재고 증가.
2. 운영 중: 기존 POS로 판매. 앱 재고는 마지막 판매 업로드까지의 추정 값이며 실제 판매마다 실시간 차감한다고 설명하지 않는다.
3. 운영 후: POS 판매 엑셀 업로드 → 메뉴별 레시피로 재료 차감 → 판매 수량·매출·소비량·현재 재고 리포트 → 반영 직후 발주 판단 알림.
4. 다음 영업 시작 3시간 전: 최신 재고·가격으로 다시 판단하고 별도 알림. 업로드 직후 알림과 각각 발송.

점주의 이점: 재고를 매번 눈으로 세는 부담 감소, 부족 예상과 구매 가격의 근거 확인, 구매 기록과 실제 입고의 구분, 하루 판매 결과 확인.

## 이번 백엔드에서 완료한 내용

- 프로젝트 POS xlsx 검증·즉시 반영, 메뉴코드 연결, 레시피 단위 환산 및 재료별 소비 기록.
- 점주별 트랜잭션·DB 잠금으로 POS 업로드/입고/기존 재고 변경 직렬화. 오류 시 전체 롤백. 동일 파일 중복 차감 및 동일 영업일 재반영 방지.
- 발주 기록과 입고 분리. 배송 대기/입고 완료 필터, 전체 수령 입고, 중복 입고 방지. 기존 발주는 `LEGACY`로 구분.
- 당시 판매·소비량을 저장하는 운영 리포트. 재고는 조회 시점의 현재 값으로 명시.
- POS 소비 이력 기준 30일 일평균 및 발주량 계산 연결. 판매 자료가 없으면 판단 근거 부족 표시.
- 업로드 후 알림 및 영업 시작 3시간 전 알림. 이벤트별 중복 방지, 커밋 후 발송, 재시도·상태 조회. 기존 종료 전 알림/가격 수집 직후 알림은 기본 비활성화.
- 모바일 계약 보완: 인증 실패 401, 중복 가입 409, 가격 JSON `isLowest`/`isDiscount`, 최저가 응답 `unit`.
- 빈 DB에서 Flyway 실행이 가능하도록 JPA 선행 테이블 bootstrap 추가. 기존 V001~V008은 수정하지 않음.
- demo 프로필 전용 합성 데이터·오늘 날짜 POS 샘플·영업 전 수동 트리거. 기존 데이터 초기화/덮어쓰기 없음.

## 팀원 작업 이후 총괄이 할 일

- 실제 앱에서 파일 선택→업로드→오류 표시→재고/리포트 갱신 검증.
- 앱 외부 사이트 복귀→주문 기록→배송 대기→입고 완료 전체 흐름 검증.
- Firebase 서비스 계정 및 Android/iOS 설정을 맞추고 실제 기기에서 두 알림 수신·누른 뒤 화면 이동 검증.
- 심상묵이 검증한 실제 가격·단위·레시피 데이터로 숫자 재확인. 합성 데이터 검증을 실제 시세 검증으로 표현하지 않음.
- 통합 레포/시연 APK 구성 및 4분 시연 리허설.
