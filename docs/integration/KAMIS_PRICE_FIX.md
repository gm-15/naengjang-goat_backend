# KAMIS 가격 정합성 수정과 적재 확인

기준: 병합된 PR #3 (`abd361b`) 이후 `fix/kamis-price-integrity`. 검증일: 2026-10-16(한국 시간).

## 수정된 동작

- KAMIS `p_product_cls_code=02` 도매를 기본으로 사용한다. `KAMIS_API_PRODUCT_CLASS=01`로 소매 수집을 명시할 수 있다. 응답의 `dpr1/dpr2/dpr4`는 서로 다른 날짜 가격이며 소매/도매 구분이 아니다.
- 도매 현재 관측은 `wholesale_price`, 소매 현재 관측은 `retail_price`에 저장한다. `dpr4`를 현재 가격으로 저장하지 않는다.
- 한국 시간의 이전 평일부터 조회하고, 공휴일/자료 없음이면 이전 평일을 조회한다. 성공한 요청 날짜를 DTO로 전달한다. `dpr2`는 응답에 실제 관측 날짜가 있는 경우에만 대체하며, `1일전`을 임의로 달력 하루 전으로 계산하지 않는다.
- 품목·품종·등급·유통 구분으로 관측 식별자를 만든다. 같은 관측일 자료의 재실행/동시 실행은 유일 인덱스와 upsert로 중복을 막고 정정 가격을 갱신한다.
- 코드가 등록된 점주와 이름만 등록된 점주를 함께 매칭한다. 이름이 같아도 다른 코드가 명시된 재료에는 저장하지 않는다.
- Processor는 값 변환과 점주별 재료 연결만 수행한다. Writer에서 chunk 트랜잭션으로 저장한다. 저장 후 오류가 발생하면 해당 chunk 전체가 롤백된다. Processor의 null은 필터이며 롤백 사유가 아니다.
- 상세/목록/추이/발주 판단이 같은 출처·유통 구분·관측 계열을 사용한다. 일별 중복은 최신 행 하나를 쓰고, 평균은 달력상 7일/30일 범위의 확보된 관측일로 계산한다. EKAPE 100g 단가도 원/kg로 정규화한다.
- 가장 최근 유효 관측을 기준으로 계열을 선택한다. 같은 날짜에는 도매 우선, 출처·등급명·품종명·관측 식별자 순으로 결정한다. 품종·등급이 다른 자료를 한 평균에 합치지 않는다. 상세/추이에 선택한 `priceBasis`, `priceSource`, `kindName`, `grade`, `unit`을 추가하고 웹·앱에 표시한다.

## V011과 기존 데이터

V001~V010 파일의 checksum은 변경하지 않는다. V011은 `price_basis`, `observation_key`, `kind_name`, `grade`와 신규 관측 유일 인덱스를 추가한다.

- 기존 KAMIS: 채널·날짜를 복원할 근거가 부족하므로 `LEGACY`로 보존하고 신규 가격 비교에서 제외한다. 과거 가격을 임의로 변환하거나 삭제하지 않는다. 업데이트 직후 재수집 전에는 비교 가격이 비어 있을 수 있다.
- 기존 EKAPE: 명시된 소비자가격이므로 `RETAIL`로 분류한다.
- 기존 DEMO: 합성 시연 자료의 가격 필드에 맞춰 분류한다. 실가격으로 취급하지 않는다.
- 신규 KAMIS: 실제 조회 기준과 관측 식별자를 갖고 수집된다. 필요한 과거 평균을 채우려면 같은 기준의 실제 일별 자료를 수집해야 한다. 이번 수정은 30일 실자료 자동 backfill을 추가하지 않는다.

실제 로컬 DB에 적용하기 전 기존 방식대로 백업하고 Flyway 이력을 확인한다. 오류를 피하려고 임의 repair/baseline으로 이력을 덮지 않는다.

## 공식 KAMIS 실데이터 상태

현재 클라우드에는 팀원/사용자 PC의 DB나 덤프가 연결되어 있지 않다. 새로 만든 검증 DB `goat_price_verify`에서 공식 서버 호출을 시도했다.

- 공식 `www.kamis.or.kr`: 클라우드 egress proxy의 403 접근 거부.
- 실제 배치: `FAILED`, HTTP 502, read/write 0.
- 이 검증 DB의 실제 KAMIS 가격: 0행. 실데이터 적재 검증은 완료되지 않았다.
- 이 결과는 팀원 PC에서 적재가 실패했다는 뜻이 아니다. 팀원 로컬 검증 보고와 이번 클라우드 결과는 별도다.
- 환경 설정 초안에 `www.kamis.or.kr`을 추가했다. 사용자 설정 저장·게시로 허용된 뒤 실제 배치를 다시 확인해야 한다. 초안 저장만으로 실행 중인 네트워크 정책이 바뀌지는 않는다.

상태 증거는 [실제 호출 결과](evidence/kamis-live-verification.json), [기존 DB 업그레이드 결과](evidence/kamis-upgrade-verification.json)를 참고한다.

## 내 PC에서 재확인

1. 이 수정이 포함된 브랜치를 받고 서버를 재실행한다. V011 적용을 확인한다.
2. `demo` 프로필과 demo 계정을 쓸 경우 다음 스크립트를 실행한다. 다른 계정이면 `--username`을 지정하며 암호는 프롬프트 또는 `KAMIS_VERIFY_PASSWORD` 환경변수로 입력한다.

```powershell
python scripts/verify-kamis-batch.py --base-url http://localhost:8080
```

3. 스크립트는 실제 수집을 두 번 요청한다. `COMPLETED`와 `writtenItems > 0`을 모두 확인한다. 읽기는 있지만 저장 항목이 0이면 해당 DB의 재료 이름·`kamis_item_code` 연결을 확인한다. `writtenItems`는 매칭된 입력 항목 수이며 점주별 실제 저장 행 수와 다를 수 있다.
4. Workbench 등에서 실제 서버가 쓰는 DB를 선택하고 [읽기 전용 점검 SQL](../../scripts/audit-kamis-data.sql)을 실행한다. 신규 가격 수, 관측일, 잘못된 필드, 중복을 확인한다.
5. 웹/앱의 가격 상세·추이에서 같은 가격, 도매/소매 기준, 품종·등급, 관측일을 확인한다. 이 JS 화면 변경 자체는 네이티브 모듈을 추가하지 않는다.

기존 POS/배송 입고 시연과 Firebase 실기기 검증 범위는 [통합 실행 안내](RUNBOOK.md)를 따른다.
