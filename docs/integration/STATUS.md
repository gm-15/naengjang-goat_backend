# 통합 구현 상태와 팀원 확인

## 구현된 범위

- 웹·Android를 최신 백엔드 저장소에 통합. 기존 화면·Firebase 설정을 출발점으로 유지.
- 구매 기록 시 즉시 입고 제거, 상품명/링크·구매 단위·포장 크기·단가/총액 확인.
- 배송 대기/입고 완료/기존 기록 필터, 전체 수령 입고, 중복/오류 안내와 조회 갱신.
- POS 양식 다운로드, 메뉴·레시피 실제 소모량 설정, 메뉴코드 연결, 파일 업로드와 중복·실패 안내.
- 영업일별 판매금액·메뉴 판매수량·소비량·조회 시점 현재 재고 리포트.
- 현재 발주 판단과 알림 당시 판단 분리, 미반영/설정 부족/소비·가격 자료 부족 표시.
- 모바일 권한·FCM 등록/갱신·수신/상세, 로그인 전 누른 알림 이어 보기, 계정/서버별 중복 방어.
- 같은 기기 토큰의 계정 소유권 이동, 현재 기기만 조건부 로그아웃 해제, 토큰 동시 등록 제약.
- 온보딩 재요청 시 실제 수정된 메뉴·레시피 보존. 타인 재고 배치 조회 차단.

검증 숫자와 실기기 확인 범위는 PR 설명의 최종 결과를 기준으로 확인합니다. 코드 빌드·HTTP/브라우저 검증과 실제 기기 설치/푸시 수신은 별도입니다.

## 김건우 — 프론트·모바일 확인

- `feat/integrated-owner-workflow` 코드와 새 APK 빌드 사용. 이전 APK에는 새 파일 선택 모듈이 없음.
- 실제 폰 파일 앱에서 POS xlsx 선택·업로드, 화면 폭/키보드/날짜 선택/뒤로 가기 확인.
- 실제 서버 UPLOAD/OPENING 알림을 앱 켜짐·백그라운드·종료 상태에서 받고 해당 상세 확인.
- 로그아웃 상태 알림 탭 후 로그인 상세 복귀, 재로그인/서버 주소 전환 확인.
- 실제 네이버/식자재왕 링크 복귀와 상품명·포장 입력의 사용성 확인.

## 심상묵 — 데이터 확인

- 실제 시연 메뉴·레시피 1인분 소모량과 POS 메뉴 연결 검증. 템플릿 기본 수량으로 발표하지 않음.
- 실제 초기 재고·유통기한·입고일, 구매 상품 포장 크기·가격 기준 확인.
- KAMIS/EKAPE 관측일·출처·단위·등급·결측 검증. 시장 평균가와 실제 구매 상품 가격을 구분.
- 합성 시연 자료를 실제 자료로 바꿀 경우 소비·재고·가격 신호 기대 숫자 제출.

## 박건우 — 통합 총괄 확인

- 최종 서버 실행 설정과 V010 적용, 실제 Firebase 서버 서비스 계정 경로 확인.
- 실제 폰·확정 데이터로 POS→리포트→판단→외부 구매 기록→배송→입고 E2E 최종 확인.
- 영업 시작 3시간 전 실제 스케줄 발송과 demo 강제 트리거 검증을 구분.
- [실행 안내](RUNBOOK.md) 기준으로 발표용 환경/새 시연 DB 준비.

추가 화면을 각 팀원이 처음부터 구현해야 하는 상태는 아닙니다. 현재 남은 팀원 작업은 기기·실자료 확인과 그 과정에서 발견되는 보정입니다.
