## 문제와 결과

기존 메인의 dpr4(2주 전 가격) 현재가 오용과 수집·저장 날짜 불일치를 수정합니다. PR #3의 도매 조회 전환 이후 현재가가 소매 필드에 저장되는 문제와, 독립 커밋 후 재처리 시 중복 위험도 함께 보완합니다. 가격의 유통 구분·관측일을 명시하고 같은 관측의 중복 저장과 실패 후 부분 커밋을 막습니다.

## 변경 사항

- 요청한 소매/도매 기준에 맞춰 dpr1을 저장. dpr2 대체는 응답의 실제 날짜가 있을 때만 허용. dpr4 현재가 오용 제거.
- 한국 시간의 조회일을 DTO로 전달하고 공휴일 대체 조회일도 보존. 접근/인증/전체 무자료 실패를 성공으로 숨기지 않음. 배치 API에 read/filter/write 수와 실패 시 HTTP 502 제공.
- 코드 등록 여부가 다른 점주가 섞여도 미등록 재료를 누락하지 않고, 명시된 다른 코드는 존중.
- Writer에서 chunk 트랜잭션으로 저장. V011 관측 유일 키와 upsert로 재실행·동시 실행·가격 정정 처리.
- 기존 KAMIS 자료는 LEGACY로 보존해 신규 도매 평균과 분리. 원본 행·값을 삭제하거나 임의 재해석하지 않음.
- 가격 상세·추이·발주 판단을 같은 출처/유통 구분/품종/등급 시계열과 원/kg 단가로 통일. 웹·앱에 가격 기준 표시.
- 로컬 배치 확인 스크립트와 읽기 전용 DB 점검 SQL 추가.

## 검증

- 전체 백엔드 64개 통과: 기존 43개 + 신규 21개. 실패·오류·건너뜀 0.
- 실제 MySQL/Spring Batch: 여러 점주 저장, 중복 없는 가격 정정, 동시 적재, 저장 직후 강제 실패 전체 롤백, 동일 작업 재시작 확인.
- 현재가 2,000원/dpr4 1,000원 입력에서 가격 API·추이 모두 현재가 2,000원 확인.
- 별도 V010 DB를 V011로 업그레이드해 기존 2행과 값 보존 확인.
- 웹 타입 검사·빌드, 모바일 타입 검사·단위 검사 26개·Android/Hermes 번들 통과.

## 실데이터 확인 제한

공식 KAMIS는 현재 클라우드 네트워크 정책의 403으로 접근할 수 없습니다. 실제 배치는 FAILED/HTTP 502/read-write 0이고, 새 검증 DB의 실가격은 0행입니다. **실 KAMIS 적재 성공으로 보고하지 않습니다.** 회귀 검사는 가상 API 응답과 실제 MySQL을 사용했습니다. 팀원/사용자 PC의 DB 상태는 별도로 확인해야 합니다.

기존 KAMIS는 LEGACY로 분리되므로 재수집 전 가격 화면이 비어 있을 수 있습니다. 같은 기준의 과거 관측이 없으면 30일 실자료가 채워진 것으로 표시하지 않습니다. 상세 검증과 적용 절차는 [KAMIS 수정 안내](KAMIS_PRICE_FIX.md)를 참고합니다.
