원본 파일은 저장소에 포함하지 않는다. 적재하려면 제공자에게 같은 파일을 받아야 한다.

## 적재 규칙

- `price_basis='RETAIL'`, `unit='kg'`, `observation_key='CSV_SEED'` 로 넣는다. **도매 수집 자료(`WHOLESALE`)와 같은 계열로 섞지 않는다.**
- 원 단위가 `kg`·`100g` 이 아닌 **187행은 제외한다.** kg 라벨 행과 비교하면 1/10~1/20 수준이라 환산이 한 번 더 적용된 것으로 보인다.

  | 재료 | kg 라벨 중앙값 | 박스 라벨 중앙값 | 비율 |
  |---|---|---|---|
  | 명태 | 2,311 | 122 | 0.05배 |
  | 배추 | 980 | 56 | 0.06배 |
  | 건고추 | 21,547 | 728 | 0.03배 |

  예: 명태 `20kg / 2,438원 → 122원/kg`. 20kg 상자가 2,438원일 수 없다. 제공자 확인이 필요하다.
- 같은 재료·출처·날짜에 여러 행이 있으면(최대 6행) **중앙값 하나로 합친다.**
  - ⚠ CSV 에 품종·등급 컬럼이 없어 **서로 다른 품종·등급이 섞였을 수 있다.** 합친 값은 시연용 대표값이고 공식 관측 1건이 아니다.
  - 품종·등급·도매/소매 컬럼이 포함된 CSV 를 다시 받으면 계열을 보존해 적재할 수 있다. 그 전까지 이 시드로 품목 간 정밀 비교를 주장하지 않는다.
- 적재 결과: 3,298행 (KAMIS 소매 2,205행 9품목 / EKAPE 소매 1,093행 4품목).

## 실행

```bash
python -m pip install PyMySQL
DB_PASSWORD=<비밀번호> python scripts/seed-market-price-csv.py \
  --csv <CSV 경로> --database naengjang_goat_demo --user-id 1
```

- 재실행하면 같은 `observation_key` 를 지우고 다시 넣는다(중복 없음).
- 제거: `DB_PASSWORD=<비밀번호> python scripts/seed-market-price-csv.py --database naengjang_goat_demo --remove`
- 재료 이름이 해당 점주에 없으면 건너뛰고 목록을 출력한다(마늘·대파·오징어는 CSV 에 없음).

## 화면에서 확인된 동작과 한계

- 적재 후 `GET /prices/{id}`·`/trend` 가 1년치로 채워진다. 예: 배추 1,292원/kg(2026-10-16), 30일 평균 1,514원 → 14.7% 저렴(채소 임계값 17% 미달로 신호 없음), 삼겹살 28,550원/kg → 4.8% 저렴(축산 임계값 8% 미달).
- **실제 KAMIS 수집(도매)을 한 번 돌리면 화면 계열이 도매로 바뀌고 이 소매 시드는 표시에서 빠진다.** 배추 추이가 18포인트 → 1포인트가 되는 것을 확인했다. 출처·유통 구분·품종·등급을 분리해 비교하는 설계이므로 정상 동작이다.
- 따라서 둘 중 하나를 택해야 한다.
  1. 시연 DB 에서는 수집을 돌리지 않고 이 소매 시드만 사용한다.
  2. **도매 기준 과거 자료**를 확보해 수집 계열과 같은 기준으로 채운다. (권장)
