# 냉장 G.O.A.T 웹

최신 백엔드와 함께 실행하는 점주 화면입니다. 기존 Figma 화면을 바탕으로 판매 마감, 발주 판단, 구매 기록과 배송 입고를 연결했습니다.

메뉴·레시피 설정과 최초 데이터 준비를 포함한 전체 실행 순서는 [통합 실행 안내](../docs/integration/RUNBOOK.md)를 참고하세요.

```bash
cp .env.example .env
npm ci
npm run dev
```

Spring 서버는 이 저장소 루트에서 실행합니다. 기본 주소는 `http://127.0.0.1:8080`입니다. 다른 주소를 사용하면 `.env`의 `VITE_API_TARGET`을 바꾸고 개발 서버를 다시 실행하세요. 개발 서버가 인증 헤더와 POS 파일을 Spring 서버로 전달합니다.

- 마감: `.xlsx` 판매 파일 업로드, POS 메뉴코드 연결, 날짜별 운영 리포트
- 발주: 최근 판매에 따른 재고 소진·권장 구매량·가격 판단
- 구매·배송 기록: 구매 시 배송 대기로 저장, 실제 수령 후 입고
- 재고: 초기 재고 및 구매 기록 없는 입고 등록, 남은 배치 조회
- 설정: 영업 시간·발주 요일 설정. 영업 시작 3시간 전 알림과 판매 업로드 후 알림은 서버에서 발송하며 모바일 앱에서 수신합니다.

POS 파일은 `판매내역` 시트, 첫 행 `영업일`, `메뉴코드`, `메뉴명`, `판매수량`, `판매금액` 순서이며 한 파일에 하루의 메뉴별 합산 내역을 담습니다. 메뉴코드가 없으면 등록 메뉴명과 정확히 같은 이름으로 연결합니다. 주문 취소·환불, 수동 판매 입력은 이번 범위에서 제외합니다.

```bash
npm run build
npm run typecheck
```

배포 환경은 웹 페이지 경로를 `index.html`로 연결하고 API 경로를 Spring 서버로 전달해야 합니다. API 서버가 별도 도메인이라면 빌드 전에 `VITE_API_BASE_URL`을 설정하고 서버 CORS에 웹 도메인을 등록하세요. 이 파일과 `.env`에는 Firebase 서비스 계정 등 비밀키를 넣지 않습니다.
